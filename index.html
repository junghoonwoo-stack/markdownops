A collaboration pattern for AI-native organizations

Markdown is the new
organizational source of truth.

Software shipped faster because code was already agent-readable. Most non-engineering work is still trapped in slides, meetings, and decks. MarkdownOps moves business artifacts — sales requirements, productization proposals, PRDs, design briefs — into Markdown that AI agents can read, review, and route. Humans show up to decide.

소프트웨어 개발은 코드가 본래 agent-readable이어서 빨라졌다. 비개발 업무는 여전히 슬라이드·회의·문서에 갇혀 있다. MarkdownOps는 영업요구조건서·상품화 발의서·PRD· 디자인 발의서 같은 비즈니스 산출물을 AI agent가 읽고 리뷰하고 라우팅할 수 있는 Markdown으로 옮긴다. 사람은 결정하기 위해 등장한다.

The bottleneck 병목

The slowest node sets the speed. 가장 느린 노드가 전체 속도를 정한다.

In the AI era, organizational speed isn't limited by developer cognition. It's limited by the loop between business, product, design, and engineering — and that loop runs on documents only humans can read. AI 시대 조직의 속도는 개발자 개인의 인지가 아닌, 영업·상품·디자인·엔지니어링 사이 상호작용 루프에서 제한된다. 그 루프는 사람만 읽을 수 있는 문서 위에서 돈다.

  • ● Decisions wait for the next meeting. 결정은 다음 회의를 기다린다.
  • ● Each person rebuilds context from scratch. 각 사람이 매번 맥락을 처음부터 다시 쌓는다.
  • ● Audit trails live in chat threads and slide footers. 감사 기록은 채팅 스레드와 슬라이드 풋노트에 흩어져 있다.
  • ● AI agents can't help — the source isn't theirs to read. AI agent는 도울 수 없다 — source가 그들이 읽을 형태가 아니다.

Today's flow 현재의 흐름

The pattern 패턴

Markdown becomes the intermediate representation. Markdown을 조직의 중간 표현으로 삼는다.

Every major work artifact gets a Markdown source. People don't write it manually — their AI agent does. The Markdown attaches to a coordination issue. Other people's agents read it in their own context, post structured reviews, and surface diffs and risks. Humans approve, reject, or revise. Decisions log to the same coordination layer. 모든 중요한 산출물이 Markdown source를 갖는다. 사람이 직접 쓰지 않는다 — 그 사람의 AI agent가 쓴다. Markdown은 협업 이슈에 첨부된다. 다른 사람의 agent가 자기 맥락에서 읽고 구조화된 리뷰를 남기며, 차이와 리스크를 정리한다. 사람은 승인·반려·수정한다. 결정은 같은 협업 레이어에 로그된다.

Slides, PDFs, and dashboards become generated views, not the source of truth. 슬라이드·PDF·대시보드는 생성된 뷰가 된다. 더 이상 source of truth가 아니다.

MarkdownOps flow MarkdownOps의 흐름

Core workflow 핵심 흐름

Six steps. No meeting. 6단계. 회의 없음.

STEP 01

A person works with their agent 사람이 자기 agent와 함께 작업

Sales rep, PM, designer — they describe the need; the agent drafts. 영업·기획·디자이너가 요구를 설명하면 agent가 초안을 만든다.

STEP 02

The agent produces a Markdown artifact agent가 Markdown 산출물을 만든다

Sales requirements, productization proposal, PRD, design brief — Markdown source. 영업요구조건서·상품화 발의서·PRD·디자인 발의서 — Markdown source.

STEP 03

It attaches to a coordination issue 협업 이슈에 첨부된다

Jira, Linear, GitHub Issues, Asana — wherever decisions are already logged. Jira·Linear·GitHub Issues·Asana — 이미 결정이 로그되는 곳 어디든.

STEP 04

Stakeholder agents review in parallel 이해관계자의 agent들이 병렬 리뷰

Each agent reads the artifact in its principal's context and posts a structured review. 각 agent가 자기 사람의 맥락에서 산출물을 읽고 구조화된 리뷰를 남긴다.

STEP 05

Humans decide 사람이 결정한다

Approve, request changes, block, or escalate. Decisions log to the same thread. 승인·변경요청·보류·에스컬레이션. 결정은 같은 스레드에 로그.

STEP 06

Views are generated on demand 필요할 때 뷰를 생성한다

PDF, PPTX, dashboards — output, never the source. Always re-generate from Markdown. PDF·PPTX·대시보드는 출력일 뿐 source가 아니다. 항상 Markdown에서 재생성.

Key concepts 핵심 개념

Five invariants. Adapt the rest to your stack. 다섯 개의 불변. 나머지는 조직 스택에 맞게.

Markdown as source of truth Markdown이 source of truth

Slides, PDFs, dashboards are derived from the Markdown — not the other way around. 슬라이드·PDF·대시보드는 Markdown에서 파생된다. 반대가 아니다.

Coordination layer 협업 레이어

Jira, Linear, GitHub Issues, Asana — anywhere with status, ownership, and history. 상태·오너십·히스토리가 있는 곳이라면 무엇이든 가능. Jira·Linear·GitHub Issues·Asana.

Markdown ontology Markdown 온톨로지

Statuses, decision types, roles — defined as Markdown, version-controlled in Git. 상태·의사결정 유형·역할을 Markdown으로 정의하고 Git으로 관리한다.

Human-in-the-loop Human-in-the-loop

Agents prepare, summarize, recommend. Humans always own decisions. agent는 준비·요약·추천한다. 의사결정은 언제나 사람이 가진다.

Async by default 기본은 비동기

Meetings become optional — reserved for judgment, negotiation, escalation. Context transfer happens through the Markdown and the agents that read it. 회의는 선택이 된다. 판단·협상·에스컬레이션을 위해서만 남긴다. 맥락 전달은 Markdown과 그것을 읽는 agent들을 통해 이루어진다.
